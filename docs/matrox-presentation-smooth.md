# Optional Matrox presentation smoothing

[Matrox] PresentationSmooth=0 preserves the existing StretchDIBits path. Setting it to 1 requests Win32 GDI HALFTONE stretching for the final 4:3 viewport; the game framebuffer (640x400 RGB565), texture sampling, input mapping and F12 captures are not changed. HUD and text will also be filtered, potentially softer. This is not increased internal rendering resolution or a guarantee of bilinear quality on Wine: GDI/driver implementation determines the actual visual effect. The DLL restores borrowed DC stretch mode and brush origin; on rejected setup or blit it logs a warning and falls back to legacy scaling for the session. The existing RGB888 synthetic DLL CI probe exercises HALFTONE with native framebuffer pixel assertions. A successful API call does not prove output interpolation quality; desktop screenshots on Windows and Wine are needed. Keep off by default and independently of WorldBilinear. Reuse the same build for A/B comparison.

Higher native resolution requires separate investigation: OEM requests 640x400, exposes pitch and framebuffer to game, invokes direct framebuffer mode via msiSetParameters(NULL), and submits game coordinates at native dimensions. Increasing allocation dimensions alone could break direct movies/UI draws and input. Do not change the game framebuffer until the direct-access contract and separate scaled world rasterization are understood.
